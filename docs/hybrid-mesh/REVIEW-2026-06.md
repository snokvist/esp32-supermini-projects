# Waymesh project-wide review — 2026-06-02

Scope: the "waytastic" / waymesh family in `esp32-supermini-projects` —
`projects/waymesh-8285` (Tier 2/3, ESP8285 + SX1280) and `projects/waymesh-node`
(Tier 1 / XR2, ESP32-C3 + LR1121), plus the shared libraries they shovel over
`lib_extra_dirs` (`waymesh_crypto`, `waymesh_config`, `waymesh_beacon`) and the
`docs/hybrid-mesh/` specs. The vendored `nanopb/` tree was treated as opaque.

Method: seven parallel focused reviewers (crypto/auth, beacon wire-codec,
relay/mesh state, config store, BLE GATT, 8285 platform, build/docs). The three
highest-value findings were re-verified by hand against the source.

Severity is **impact × likelihood in the real deployment**. Many issues are
latent (need a specific trigger: failing flash, mixed fleet, many channels) —
called out per item.

---

## Recommended targets (high value, tractable)

Ordered by value-to-effort. T1–T4 are small, localized, and do **not** change
the on-air wire format (so no interop break, no coordinated re-flash needed).

| # | Target | Files | Why it's high value |
|---|---|---|---|
| **T1** | Enforce the packetId reserve-ahead contract + fix the weak/zero reseed | `waymesh_config.c` | The entire v2/auth security model rests on CCM nonce uniqueness; this is the one place it silently breaks. Tiny fix. |
| **T2** | ~~Reject `version >= 2` in the legacy v1 RX guard~~ — **superseded:** the legacy v0/v1 path was removed entirely (2026-06-02), so there is no legacy RX left to mis-parse a v2 frame. | `waymesh-8285/src/main.cpp` | Resolved by deletion. |
| **T3** | Widen 8285 `srcId` to a full 32-bit MAC hash | `waymesh-8285/src/main.cpp:642` | Aligns the nonce collision domain with the C3; removes a same-low-24-chipId nonce-collision path. Does not change the wire (srcId is already carried). |
| **T4** | Pin `board_build.flash_mode = dout` | `waymesh-8285/platformio.ini` | GPIO9/10 (RXEN/TXEN, the BetaFPV Nano PA gate) are the flash SDIO pins; only safe in DIO/DOUT. Currently unpinned = "works on this bench unit" fragility. |
| **T5** | Resize + time-bound the relay seen-set; dedup *after* the group filter | `waymesh-8285/src/main.cpp`, `board_config.h:168` | The seen-set is the *only* loop-breaker (no hop-limit). A 32-slot blind FIFO shared across all groups is flushable → relay storm / DoS amplifier. |
| **T6** | Size `kQDepth` for the real worst case + check the ConfigComplete enqueue + dedup `want_config` | `ble_gatt.cpp` | Prevents the Meshtastic app from wedging mid-pairing when several channels are provisioned. |

Quick wins worth grabbing alongside the above: the `millis()`-rollover GPS
comparison (M4), key/schedule zeroization (M1), EEPROM stale-PSK tail (M2), and
the three doc/comment drifts (D1–D3).

## Critical / High

### H1 — packetId reuse defeats CCM nonce uniqueness  ✅ verified
`projects/waymesh-node/lib/waymesh_config/waymesh_config.c:111-116,151-155`
(cross-confirmed by crypto + relay + config reviewers)

`wm_config_next_packet_id` ignores `pid_reserve`'s return:
```c
if (cfg->pid_next == cfg->pid_ceiling)
    (void)pid_reserve(cfg);   /* "device backend must guarantee this write" — but nothing enforces it */
return cfg->pid_next++;
```
On a flash-write failure `pid_reserve` returns `-1` and leaves `pid_ceiling`
unchanged, but the id is still issued *at* the committed ceiling and `pid_next`
runs past it. Because the guard is `==` (not `>=`), reserve-ahead then never
re-fires for the rest of the boot. After a reboot the node reloads the old
committed ceiling and **re-issues packetIds it already transmitted** → identical
CCM nonce `(packetId,srcId,chanHash)` under a long-lived PSK → AES-CTR keystream
reuse (confidentiality break) + replay acceptance. Also: line 152
`ceil = store->rng ? store->rng(store->ctx) : 0;` reseeds to **0** every boot if
`rng` is ever NULL — verify `config_nvs` actually wires `rng`.

Fix: make the contract enforced — if `pid_reserve` fails, do not issue an id
past the committed ceiling (retry the persist, or return a sentinel and skip TX);
use `>=` in the trigger; `assert(store->rng != NULL)` at init.

### H2 — relay seen-set is a flushable 32-slot FIFO; dedup runs before the group filter  ✅ verified
`projects/waymesh-8285/src/main.cpp:217-228,374-390`, `board_config.h:168`

`RELAY_SEEN_SET_SIZE = 32`, blind FIFO eviction, no time-based expiry, and the
default policy is `WM_RELAY_ALL`. Dedup (`seenContains`/`seenAdd`) and
`relaySchedule` run **before** the `WM_RX_DROP_FOREIGN_GROUP` filter, so foreign
groups compete for the same 32 slots as the home group. With "no hop-limit"
(by design, `05-protocol.md`), the seen-set is the sole loop-breaker — once it's
flushed (easy on a busy or hostile mesh), a re-arriving MessageID is re-relayed,
which evicts more entries: a self-reinforcing storm, worst exactly under load.

Fix: size for the realistic worst-case offered load with margin; make eviction
time-aware (don't evict an entry while its re-floods are still in flight);
prefer deduping only traffic that passed the group/relay-policy filter, or
document and bound the relay-all multi-group load. (The doc already flags
"Bloom-filter sizing for the seen-set" as open.)

### H3 — legacy v1 RX silently mis-parses (and re-floods) a v2 frame  ✅ resolved by removing the legacy path
`projects/waymesh-8285/src/main.cpp:479`

The `#if !WAYMESH_V2` RX path gates on magic+length+srcId but never checks
`version`. A v2 frame (`chanHash@2`, `srcNodeID@4`) is memcpy'd over the packed
v1 struct (`srcId@2`), yielding a garbage srcId, a mis-keyed dedup entry, and —
with `-DWAYMESH_RELAY` — a verbatim re-flood under the wrong `(srcId,seq)`.
Mitigated today because every production env ships `-DWAYMESH_V2=1`; the hazard
is a mixed fleet (an un-reflashed legacy node hearing a v2 neighbour).

Fix: add `&& b.version <= WM_VERSION` to the legacy RX guard.

### H4 — 8285 srcId is only 24 bits → smaller nonce collision domain
`projects/waymesh-8285/src/main.cpp:642`

`gNodeId = ESP.getChipId()` is the low **24** bits of the STA MAC; the C3 uses
the low **32** bits of the efuse MAC (`waymesh-node/src/main.cpp:393`). srcId is
a nonce input, so two 8285s sharing a low-24 chipId (and a packetId) collide.
Fix: hash the full 6-byte STA MAC to 32 bits. Wire-compatible (srcId is already
transmitted at full width).

### H5 — GPIO9/GPIO10 RF-switch pins are the embedded-flash SDIO pins; flash mode unpinned
`projects/waymesh-8285/src/board_config.h:68-75`, `platformio.ini` (no `flash_mode`)

RXEN=GPIO9 / TXEN=GPIO10 (BetaFPV Nano PA/LNA gate) are SD_DATA2/3 — only free
when the embedded flash runs in DIO/DOUT (2-bit) mode. Nothing in the repo pins
`board_build.flash_mode = dout`, and the `esptool write_flash` recipe doesn't set
it either. On the bench unit it works (our live flash showed TX+RX+relay at 100%
PDR, so this unit's flash is in a 2-bit mode) — but a QIO re-flash or a different
flash part would corrupt flash access / PA control.
Fix: pin `board_build.flash_mode = dout` in `[env:esp8285_sx1280]` and document it.

### H6 — BLE config handshake can overflow the FromRadio queue and drop ConfigComplete  ✅ verified
`projects/waymesh-node/src/ble_gatt.cpp:190,387-410`

`kQDepth = 24`, but the worst-case atomic handshake is
`my_info(1) + metadata(1) + channels(≤8) + self(1) + peers(≤16) + complete(1) = 28`.
The comment only budgeted "kMaxPeers + ~4". `queueConfigSequence` ignores the
enqueue return for the peer frames *and the terminal `config_complete_id`*
(line 410), so under load the client never sees ConfigComplete and hangs.
Compounded by H7 (no want_config dedup) — a retry stacks another ~28 frames.
Typical 1–2-channel setups stay under 24, so this bites mainly multi-channel
nodes. Fix: `kQDepth >= 2 + WM_MAX_CHANNELS + 1 + kMaxPeers + 1` (≥28) and
guarantee the ConfigComplete frame is enqueued (check return / reserve a slot).

### H7 — repeated `want_config_id` re-runs the whole handshake, no dedup
`projects/waymesh-node/src/ble_gatt.cpp:330,607-635`

The Meshtastic client retries `want_config_id` if it doesn't see ConfigComplete
(exactly the H6 failure), and each retry re-enqueues the full sequence onto a
still-draining queue → permanent wedge loop. Fix: per-connection
"handshake-queued" flag (reset in `onConnect`); flush+restart cleanly on retry.

## Medium

- **M1 — no key / key-schedule zeroization anywhere in the crypto layer.**
  `waymesh_config` holds `psk[32]` + `expanded_key[32]` for process life, and
  `wm_aes_ctx.rk`, CBC-MAC `T`, keystream `s0` are left on the stack after every
  `wm_ccm_*` / `wm_meshtastic_ctr`. RAM-dump of a captured relay recovers keys.
  Fix: `explicit_bzero`-style wipe of transient schedules; accept persistent `gCfg`.
- **M2 — EEPROM `put_blob` leaves a stale tail (old PSK lingers in flash).**
  `wm_store_eeprom.cpp:79-88` writes only `len` bytes; a shorter re-provision
  leaves the previous (longer) PSK/name readable past `chans_len`. Not a
  correctness bug (reads honour `chans_len`) but a secret-retention one.
  Fix: zero-fill `[len .. WM_EE_BLOB_MAX)` after the write.
- **M3 — EEPROM backend has no CRC; NVS does.** `wm_store_eeprom.cpp` validates
  only a 4-byte magic + sane length, so an in-blob bit-flip is accepted as a real
  channel (wrong PSK → wrong chanHash → silent loss of group membership). The
  portable `config_deserialize` is well-bounded, so no overflow — just an
  integrity asymmetry vs the C3. Fix: add a CRC16/32 over the EEPROM blob.
- **M4 — `millis()` rollover bug in the GPS grace check.**
  `waymesh-8285/src/main.cpp:547` `if (now >= GPS_GRACE_MS)` is absolute-time;
  every other timer in the file uses the rollover-safe `now - last >= period`
  idiom. After the 49.7-day wrap the GPS state machine stays stuck. Fix: anchor
  to a captured `bootMs` or a one-shot flag.
- **M5 — relay TX is blocking and can fire multiple frames back-to-back.**
  `relayService()` calls synchronous `gRadio.transmit()` in `loop()` for up to
  `RELAY_PENDING_SLOTS` (4) frames per pass; RX is deaf for the whole window
  (~tens of ms each), so an overhear that should suppress a *different* pending
  slot can't arrive → redundant rebroadcasts, partially defeating the SNR-delay
  discipline. Fix: at most one relay TX per `loop()` pass (or non-blocking
  `startTransmit()`).
- **M6 — `wm_config_add_channel` name copy relies on a prior memset for its NUL.**
  `waymesh_config.c:180` `memcpy(c->name, name, strlen(name))` — works only
  because of the line-179 memset; fragile under refactor. Fix: explicit
  `c->name[strlen(name)] = '\0'` or `strncpy` with bound.
- **M7 — 8285 GPS baud auto-detect is locked to the debug baud (115200).**
  `waymesh-8285/src/main.cpp:556-563` probes at 115200; the baud-switch block is
  `#if GPS_BAUD != 115200` (compiled out for all shipped envs). A 9600-default
  u-blox can never be *detected* to then switch to it, so the "vendor-neutral
  auto-detect any module" claim holds only for modules already at 115200.
  Fix: probe at `GPS_BAUD`, or document the 115200 requirement (and have
  `gps_provision.py` set it).
- **M8 — no GPS-detach recovery.** The UART0 state machine is one-way
  `DEBUG→PROBE→GPS` with no exit; unplugging the GPS at runtime silences the
  console until a power-cycle (documented as intentional, but a transient PROBE
  glitch then permanently kills the console + serial-`c`). Fix (optional):
  "no valid sentence for N s → revert to DEBUG" watchdog.

## Low / hardening / housekeeping

- **L1** Short (<16 B) PSKs are silently zero-padded (`channel.c:51-60`) —
  Meshtastic-faithful, but add a provisioning-time guardrail.
- **L2** Relay jitter (`main.cpp:252`) is seeded once from `gNodeId ^ micros()`,
  correlated across reboots → equal-SNR ties can resolve identically each round
  (steady duplicate floods). Reseed / widen / mix runtime entropy.
- **L3** PDR metric (`main.cpp:518`) inflates "expected" on any forward packetId
  jump (peer reboot) → understated PDR. Diagnostics-only; clamp large gaps.
- **L4** GPIO0 portal long-press (`main.cpp:606-613`) has no debounce / no
  startup guard; GPIO0 is also the PWM-ch1 header pin. Add sample-count debounce
  + ignore the first ~1 s after boot.
- **L5** Portal AP password is the compile-time shared `"waymesh-setup"` for
  every unit (`wm_portal.cpp:16`). Per §8.4 physical-proximity model it's
  accepted, but consider a per-device default derived from chipId.
- **L6** `wm_config_init` reserves a packetId block (a flash sector commit) on
  **every** boot; a boot-loop wears the 8285 EEPROM sector. Reserve only when
  `pid_next == pid_ceiling`.
- **L7** BLE peer eviction (`ble_gatt.cpp:172-181`) degenerates to always
  evicting slot 0 when there's no GPS time fix (all `lastHeardEpoch==0`). Use a
  `millis()` tick for eviction ordering.
- **L8** Inbound BLE app text 181–256 B is silently dropped (logged as "queued")
  rather than truncated (`ble_gatt.cpp:595-598`).
- **L9** `WM_EE_BLOB_MAX` is re-derived in `wm_store_eeprom.cpp:28` instead of
  imported from the lib header → drift risk if the blob format grows. Export
  `WM_CONFIG_BLOB_MAX` from the lib.
- **L10** RF params (SF/BW/CR/freq/sync/preamble) are duplicated in the two
  `board_config.h` files (values currently agree). Consider a shared header;
  they are interop-critical.

## Documentation drift (no code risk)

- **D1** `waymesh-8285/platformio.ini:23-31` base-env comment still claims the
  production envs are "byte-for-byte the verified PoC build" / "nothing extra" —
  but `bayck_7pwm` / `betafpv_nano` now set `-DWAYMESH_V2 -DWAYMESH_WIFI_CONFIG`
  and pull in `waymesh_config`+`waymesh_crypto`. No env produces the pure PoC
  binary any more.
- **D2** Same file line 27: "nanopb / waymesh_beacon stay out until the Phase-B
  v2/auth port" — that port has landed; `waymesh_beacon` is compiled into every
  v2 env. (nanopb does correctly stay out — it's BLE-proto only.)
- **D3** `docs/hybrid-mesh/09-poc-roadmap.md:114-118` says the 8285 reads GPS on
  a "SoftwareSerial mapped to a PWM-output GPIO"; the as-built firmware uses
  hardware UART0 time-sharing. (The README is correct; the roadmap doc is stale.)
- **D4** `WAYMESH_TIER=2` is set in every 8285 env but consumed by no `#if`
  (orphan flag). Drop it or surface it in the boot banner.

## Verified clean (no action — recorded so the next reviewer skips them)

- AES-CCM primitive: tag verified before plaintext is trusted; constant-time
  tag compare; zeroize-on-fail; B0/A_i length math bounded by `ccm_validate`.
- Endianness: wire is LE throughout (`rd/wr_u32le`); CCM internals BE per RFC
  3610; TX/RX reconstruct nonce+AAD identically. No byte-order bug.
- Beacon RX bounds: `wm_beacon_parse`/`wm_beacon_open` length-check every field
  read on untrusted bytes; `payload_len > pt_cap` guarded before CCM; PHY length
  capped to `WM_BEACON_FRAME_MAX`. No over-read found.
- Crypto is byte-identical across both firmwares (shared `lib_extra_dirs`); the
  only deltas are non-crypto (srcId width H4, relay primitive lives only on 8285).
- RadioLib pinned `@7.6.0` on **both** sides; TinyGPSPlus `^1.0.3` both; RF
  params + sync word `0x12` agree and PoC #0 verified interop both directions.
- BLE: phone writes decode into bounded nanopb static structs; every downstream
  `memcpy` is clamped; cross-task queues are `portMUX`-guarded; per-message id
  counters are each single-task; rate-limits use rollover-safe subtraction.
- PA/LNA gating scope is correct: `PIN_LORA_RXEN/TXEN` defined only for
  `WAYMESH_BOARD_BETAFPV_NANO`; bayck never drives GPIO9/10; RadioLib drives the
  RF switch on every TX/RX/idle with the correct IDLE/RX/TX table.
- No `delay()` starvation; blocking radio waits feed `yield()` (soft-WDT safe).
- No TODO/FIXME/HACK markers in the waymesh sources.
